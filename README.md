# Учёт выдачи книг в библиотеке

Учебный проект по дисциплине «Технологии разработки приложений на базе фреймворков».

Текущее состояние соответствует ПР1, ПР2, ПР3, ПР5, ПР6, ПР7, ПР9 и лекциям
1–3 из папки `../practices/`.
Карта требований с указанием файлов реализации:
[docs/practices.md](docs/practices.md).

## Назначение

Программа помогает библиотекарю вести каталог книг, учитывать читателей,
выдавать книги и оформлять возврат. Каждая запись каталога представляет один
физический экземпляр книги. Книга доступна для выдачи, если у неё нет
незавершённой выдачи.

## Целевая аудитория

Библиотекарь небольшой библиотеки (школьной, районной, библиотеки
предприятия), которому нужно быстро узнать, где находится книга, кто её взял
и не просрочен ли возврат.

## Предметная область

Библиотека выдаёт читателям книги на ограниченный срок (14 дней). Читатель
предъявляет читательский билет, библиотекарь проверяет, свободен ли экземпляр,
и оформляет выдачу. При возврате выдача закрывается; если срок нарушен,
начисляется штраф за каждый день просрочки.

## Основные сущности

- **Книга:** идентификатор, название, автор.
- **Читатель:** идентификатор, имя, номер читательского билета.
- **Выдача:** идентификатор, книга, читатель, дата выдачи и дата возврата.

## Основные функции

- Добавление книг и читателей.
- Просмотр каталога и поиск книг.
- Проверка доступности книги.
- Выдача книги читателю и расчёт срока возврата.
- Оформление возврата и расчёт штрафа за просрочку.
- Просмотр текущих выдач и статистики.

## Используемые технологии

- Python 3.11+;
- Django 5.2 — веб-фреймворк (с ПР5);
- Django Template Language — шаблоны страниц (с ПР6);
- HTML, CSS и Bootstrap 5.3 — оформление страниц;
- JavaScript — небольшое поведение интерфейса;
- SQLite и Django ORM — база данных веб-версии и работа с моделями (ПР9);
- pytest — автоматизированные тесты;
- flake8 — проверка качества кода.

## Страницы веб-интерфейса

| URL | View-функция | Что показывает | Django ORM (ПР9) |
|-----|--------------|----------------|--------------|
| `/` | `homepage.views.index` | описание и навигация | — |
| `/books/` | `books.views.books` | каталог с отметкой «доступна / выдана» | `annotate(Exists(...))` |
| `/books/search/?q=` | `books.views.search` | поиск по названию или автору | `Q`, `alias`, `contains` |
| `/books/available/?date=` | `books.views.available` | книги, доступные на дату | `exclude(Exists(...))` |
| `/books/<int:book_id>/` | `books.views.book_detail` | карточка книги и история выдач | `filter(pk=...)`, `select_related` |
| `/loans/` | `loans.views.loans` | текущие выдачи | `filter`, `select_related`, `Paginator` |
| `/loans/overdue/?date=` | `loans.views.overdue` | книги, остававшиеся у читателей с просрочкой на дату, штрафы | `filter`, `annotate` |
| `/loans/<int:loan_id>/` | `loans.views.loan_detail` | карточка выдачи, просрочка | `filter(pk=...)`, `select_related` |
| `/loans/readers/` | `loans.views.readers` | читатели: выдачи, книги на руках, штрафы | `annotate`, `Count`, `Sum` |
| `/loans/statistics/?min=` | `loans.views.statistics` | сводка, популярность, по месяцам, активные читатели | `aggregate`, `values`, `annotate` |

Навигация: Главная | Каталог | Выдачи | Читатели | Статистика. Поиск и
доступные книги открываются из меню раздела «Каталог», просроченные выдачи —
из меню раздела «Выдачи».

На страницах доступных книг и просрочек параметр `date` имеет формат
`ГГГГ-ММ-ДД`. Если он отсутствует или некорректен, используется сегодняшняя
дата в часовом поясе проекта (`Europe/Moscow`). Книга занята с даты выдачи
до даты фактического возврата, не включая день возврата. Будущая выдача
не занимает книгу раньше своей даты. Для будущей даты незавершённая
выдача считается продолжающейся: срок в 14 дней не гарантирует возврат.
Страница просрочек учитывает историю: книга, возвращённая 20 сентября,
может попасть в просрочки на 19 сентября, но уже не на 20 сентября.

Если книга или выдача не найдена, шаблон показывает сообщение через
`{% if %}/{% else %}`, а ответ имеет код 404. Для несуществующих адресов
подключён обработчик `handler404` (`homepage.views.page_not_found`,
шаблон `homepage/404.html`), он виден при `DEBUG = False`.

View-функции только получают данные и передают их в шаблон через контекст
вызовом `render()`; HTML в Python не формируется (функция `page()` из ПР5
удалена в ПР6). С ПР7 данные страниц берутся SQL-запросами из SQLite.

## База данных (ПР7)

С ПР7 веб-интерфейс получает данные из базы SQLite `data/library.sqlite`
через модуль `sqlite3` стандартной библиотеки (Django ORM пока не
используется). JSON-файлы остаются исходными данными и по-прежнему
используются консольной версией.

### Таблицы

| Таблица | Поле | Тип | Назначение |
|---------|------|-----|------------|
| `books` | `id` | INTEGER | первичный ключ |
| | `title` | TEXT NOT NULL | название |
| | `author` | TEXT NOT NULL | автор |
| `readers` | `id` | INTEGER | первичный ключ |
| | `name` | TEXT NOT NULL | имя читателя |
| | `ticket` | TEXT NOT NULL UNIQUE | номер читательского билета |
| `loans` | `id` | INTEGER | первичный ключ |
| | `book_id` | INTEGER NOT NULL | внешний ключ → `books.id` |
| | `reader_id` | INTEGER NOT NULL | внешний ключ → `readers.id` |
| | `issue_date` | TEXT NOT NULL | дата выдачи, `ГГГГ-ММ-ДД` |
| | `return_date` | TEXT | дата возврата; `NULL` — книга у читателя |

Связи: у книги и у читателя может быть много выдач; каждая выдача
относится к одной книге и одному читателю.

### Файлы

- `sql/schema.sql` — команды `CREATE TABLE IF NOT EXISTS` с первичными и
  внешними ключами;
- `sql/queries.sql` — 17 проверенных запросов с комментариями: списки,
  фильтрация `WHERE`, соединения `JOIN`, агрегатные функции (`COUNT`,
  `AVG`, `MAX`, `SUM`), группировка `GROUP BY`, фильтрация групп `HAVING`;
- `db/database.py` — `get_connection()` (включает `PRAGMA foreign_keys = ON`
  и регистрирует функцию `casefold()` для поиска по кириллице без учёта
  регистра), `create_schema()`, `fetch_all()` / `fetch_one()`
  (`conn.row_factory = sqlite3.Row` — доступ к полям по имени);
- `db/import_json.py` — перенос данных из JSON: создаёт таблицы, очищает
  их, вставляет записи `executemany()` в порядке книги → читатели → выдачи,
  `commit()` или `rollback()` при ошибке. До изменения таблиц проверяются
  наличие всех трёх JSON-файлов, формат записей, даты и ссылки выдач на
  книги и читателей. Ошибка проверки или вставки сохраняет прежние данные.

Все значения от пользователя (поисковая строка, дата, порог) передаются в
запросы параметрами `?`, f-строки для подстановки значений не используются.

### Создание базы и перенос данных

```
python -m db.import_json
```

Команда создаёт `data/library.sqlite` (если её нет), таблицы и переносит в
них `data/books.json`, `data/readers.json`, `data/loans.json`.
Повторный запуск заменяет содержимое таблиц актуальными данными JSON,
поэтому перед импортом изменений следует сохранить копию рабочей базы.
Локальные базы SQLite исключены из Git через `.gitignore`.

## Django ORM (ПР9)

`books.Book` хранит название и автора. `loans.Reader` хранит имя и
уникальный номер билета. `loans.Loan` связывает экземпляр и читателя
через два внешних ключа с `PROTECT` и обратным именем `loans`.
Дата возврата может быть пустой или совпадать с датой выдачи. Срок
возврата и штраф вычисляются из дат и правил предметной области.

Миграции создают таблицы в `db.sqlite3`. Команда `import_pr7` читает
предыдущую БД в режиме чтения и переносит данные с сохранением ID и
связей одной транзакцией. Повторный импорт тех же строк безопасен.
При конфликте с изменённой строкой импорт откатывается. Исходную рабочую
базу можно выбрать через `--source /путь/к/library.sqlite`.

Список текущих выдач фильтруется по дате выдачи, названию книги и имени
или билету читателя. Сортировка и параметры фильтра сохраняются при
переключении страниц. Звено ПР7 (`db/`, `sql/`) сохранено для проверки и
переноса данных. Веб-представления используют Django ORM.

## Возможности консольной версии

Консольное приложение с меню:

- просмотр каталога (сортировка по названию);
- поиск книг по названию или автору;
- проверка доступности книги;
- добавление книг и читателей;
- выдача книги читателю с расчётом срока возврата (14 дней);
- оформление возврата с расчётом штрафа за просрочку (10 руб. в день);
- просмотр текущих выдач;
- статистика: сколько книг выдано, доступно и просрочено.

Функции начального сценария ПР1 (`get_book_status()`, `calculate_due_date()`,
`calculate_overdue_days()`, `calculate_fine()`) сохранены в модуле
`models/loans.py` и используются методами класса `Loan`.

## Классы предметной области (ПР3)

### LibraryObject — объект учёта (`models/base.py`)

Базовый класс: атрибут `id` и метод `to_data()`, который каждый наследник
переопределяет по-своему (полиморфизм). Благодаря этому `storage.py`
сохраняет книги, читателей и выдачи одной функцией `save_objects()`.

### Book — книга (`models/books.py`)

- атрибуты: `id`, `title`, `author`;
- `from_data()` (`@classmethod`) — создание из словаря JSON;
- `to_data()` — словарь для JSON;
- `validate_text()` (`@staticmethod`) — проверка непустой строки;
- `info` (`@property`) — краткое описание «Название», автор;
- `matches()` — проверка совпадения с поисковым запросом;
- `__str__()` — строка для вывода в каталоге.

### Reader — читатель (`models/readers.py`)

- атрибуты: `id`, `name`, `ticket`;
- `from_data()`, `to_data()`, `has_ticket()`, `__str__()`.

### Loan — выдача (`models/loans.py`)

- атрибуты: `id`, `book` (объект `Book`), `reader` (объект `Reader`),
  `issue_date`, закрытый `_return_date`;
- свойства `return_date`, `is_active`, `due_date` (`@property`);
- `close()` — оформление возврата (нельзя вернуть дважды или раньше выдачи);
- `overdue_days()`, `fine()` — просрочка и штраф;
- `to_data()`, `__str__()`.

### Взаимодействие объектов

Выдача хранит ссылки на объекты книги и читателя, поэтому данные доступны
напрямую: `loan.book.title`, `loan.reader.name`. При возврате выдача не
удаляется, а закрывается методом `close()` — история выдач сохраняется.
В JSON выдача записывается с идентификаторами `book_id` и `reader_id`;
при загрузке `storage.load_loans()` находит по ним объекты `Book` и `Reader`.

Функции работы с коллекциями (`add_book()`, `find_books()`, `sort_books()`,
`issue_book()`, `return_book()`, `get_statistics()` и др.) остались обычными
функциями и работают со списками `List[Book]`, `List[Reader]`, `List[Loan]`.

Отсутствующий JSON-файл в консольной версии означает пустую коллекцию.

При импорте в SQLite отсутствие любого исходного файла считается ошибкой,
чтобы случайно не удалить данные уже заполненной базы.

## Формат JSON-данных

Исходные данные хранятся в каталоге `data/` в виде списков словарей.

`books.json`:

```json
[{"id": 1, "title": "Мастер и Маргарита", "author": "М. А. Булгаков"}]
```

`readers.json`:

```json
[{"id": 1, "name": "Иван Петров", "ticket": "Б-0042"}]
```

`loans.json` (`return_date` равен `null`, пока книга не возвращена):

```json
[{"id": 1, "book_id": 1, "reader_id": 1,
  "issue_date": "2026-09-01", "return_date": "2026-09-20"}]
```

При загрузке записи JSON превращаются в объекты `Book`, `Reader` и `Loan`,
даты — в объекты `datetime.date`; при сохранении выполняется обратное
преобразование.

## Запуск программы

Веб-версия (Django):

```sh
python manage.py migrate
# Для новой копии проекта без базы ПР7 создайте её из примеров:

python manage.py runserver
```

При наличии рабочей `data/library.sqlite` пропустите `db.import_json`

Консольная версия (сохранена):

```
python main.py
```

## Запуск тестов

```
python manage.py check
pytest -v
```

Тесты проверяют классы и JSON, импорт и откат транзакций, все 17 запросов
из `sql/queries.sql`, именованные URL, наследование шаблонов, поиск по
кириллице, фильтрацию по дате, статистику, пустую базу и ответы 404.

база SQLite; рабочие JSON-файлы и базы не изменяются. Дополнительный
пакет `pytest-django` не требуется.
