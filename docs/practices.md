# Соответствие учебным материалам

Проект «Учёт выдачи книг в библиотеке» продолжает одну предметную область
через ПР1, ПР2, ПР3, ПР5, ПР6, ПР7, ПР9 и ПР10. Использованы материалы из
`../../practices/` и три лекции. Веб-страницы получают данные через Django ORM.

## Практические работы

| Материал | Требование к индивидуальному проекту | Где показано |
|---|---|---|
| ПР1 — основы Python | Не менее трёх функций законченного сценария, условия, даты, импорты | `models/loans.py`: `get_book_status`, `calculate_due_date`, `calculate_overdue_days`, `calculate_fine`; сценарии выдачи и возврата в `main.py` |
| ПР2 — продолжение Python | Коллекции, циклы, функции, модули, исключения, JSON, `with`, генераторы, сортировка, pytest и flake8 | `main.py`, `utils.py`, `storage.py`, функции коллекций в `models/`, `tests/`, `setup.cfg` |
| ПР3 — ООП | Классы сущностей, конструкторы, методы, `__str__`, взаимодействие объектов, сохранение JSON и функций коллекций | `LibraryObject`, `Book`, `Reader`, `Loan` в `models/`; выдача хранит объекты книги и читателя; `storage.py` преобразует их в JSON и обратно |
| ПР5 — основы Django | Существующий проект, приложения, маршруты, динамические URL, view-функции, навигация и 404 | `library/`, приложения `homepage`, `books`, `loans`, их `urls.py` и `views.py`, `handler404` |
| ПР6 — шаблоны | `render`, контекст, базовый шаблон, наследование, включения, условия и циклы, именованные URL, фильтры, статика | `templates/base.html`, `templates/includes/`, шаблоны приложений, `homepage/static/homepage/` |
| ПР7 — SQL | SQLite, PK/FK, импорт JSON, `sqlite3.Row`, параметры `?`, не менее 10 запросов, поиск доступных объектов по дате, статистика | `sql/schema.sql`, 17 запросов в `sql/queries.sql`, `db/database.py`, `db/import_json.py`, `books/views.py`, `loans/views.py` |
| ПР9 — Django ORM | Модели, миграции, перенос БД, запросы и пагинация | `books/models.py`, `loans/models.py`, `import_pr7`, представления каталога и выдач |
| ПР10 — Django Admin и ORM | Админка, связанные записи, статусы, QuerySet, анализ SQL | `books/admin.py`, `loans/admin.py`, `loans/models.py`, Debug Toolbar |

Имена и сценарии адаптированы к библиотеке. Учебный пример бронирования
помещений не копируется: вместо поиска свободных помещений реализован
поиск доступных экземпляров книг на выбранную дату.

## Лекции

| Лекция | Применение |
|---|---|
| 1 — введение во фреймворки | Разделение ответственности: предметные классы, файловое хранилище, слой SQL, представления и шаблоны. Единый стиль Python и автоматические проверки |
| 2 — основы Django 5.2 | Настройки проекта, приложения в `INSTALLED_APPS`, `path` и `include`, динамические адреса `<int:book_id>` и `<int:loan_id>`, GET-параметры, обработка отсутствующих объектов |
| 3 — шаблоны Django | `render(request, template, context)`, `extends`, `block`, `include`, `for/empty`, `if`, `url` с пространствами имён, `load static`, фильтры `date`, `default`, `default_if_none`, `length`, `floatformat` |

Используются приёмы, необходимые сценариям проекта. Например, собственные
конвертеры URL и пользовательские теги шаблонов не добавляются искусственно:
имеющихся конвертеров и стандартных тегов достаточно.

## Сохранение результатов предыдущих этапов

- Консольное меню работает с объектами `Book`, `Reader`, `Loan` и JSON.
- Наследование и полиморфизм показаны через `LibraryObject.to_data()`:
  `save_objects()` сохраняет разные типы объектов одной функцией.
- Инкапсуляция показана в `Loan`: дата возврата доступна через свойство,
  а `close()` не позволяет вернуть книгу дважды или раньше выдачи.
- `@staticmethod`, `@classmethod` и `@property` используются в классах
  предметной области.
- SQL-слой ПР7 и файлы запросов сохранены. Таблицы веб-версии создаются
  командой `migrate`; данные ПР7 переносит `import_pr7`.
- Страницы используют наследование HTML-шаблонов и существующую навигацию.

## SQL и даты

В `sql/queries.sql` есть два запроса списков, три запроса фильтрации,
пять запросов соединения таблиц, два сводных запроса и пять запросов
группировки. Среди них есть `SELECT`, `WHERE`, `JOIN`, `LEFT JOIN`,
`COUNT`, `AVG`, `MAX`, `SUM`, `GROUP BY` и `HAVING`.

Даты передаются в SQLite в формате ISO. Пользовательские значения
передаются отдельно от текста SQL параметрами `?`. Для поиска по
кириллице соединение регистрирует функцию `casefold()`.

`/books/available/?date=2026-09-19` исключает книги с выдачей, начавшейся
не позже выбранного дня и ещё не завершившейся на этот день. День возврата
считается первым доступным днём. Незавершённая выдача занимает книгу и
на будущие даты: расчётный срок возврата не заменяет фактический возврат.

`/loans/overdue/?date=2026-09-19` показывает выдачи, остававшиеся
незавершёнными на выбранный день, с истёкшим сроком в 14 дней. При
проверке прошлых дат учитываются и выдачи, закрытые позднее. В сам день
срока возврата просрочка равна нулю. Штраф — 10 руб. за день.

## Проверка

Из корня `library-lending/`, в активированном окружении:

```sh
python manage.py check
python -m pytest -v
python -m flake8 .
```

Тесты используют временные файлы и SQLite-базы. Проверяются обычные,
пустые и ошибочные наборы данных, граничные даты, SQL-параметры,
кириллический поиск, страницы, шаблоны, 404 и сохранность данных при
ошибках импорта. Для первой подготовки рабочей базы:

```sh
python manage.py migrate
# При отсутствии исходной базы ПР7:
python -m db.import_json
python manage.py import_pr7
python manage.py runserver
```

Импорт заменяет содержимое таблиц книг, читателей и выдач данными JSON.
Он проверяет исходные файлы до изменения таблиц и откатывает изменения
при ошибках SQL. Перед заменой рабочей базы следует сохранить её копию.
